# Dexter Launcher UI - guide for AI coding agents (Claude Code, Codex, Cursor)

This folder is the **finished UI** of the Dexter Minecraft launcher: an Electron app with every screen designed and working with sample data.
Your job is to **build the real launcher behind this UI, not to redesign it.** Keep the look exactly as it is.

## Run it

```bash
npm install
npm start          # opens the launcher (sign-in card first, then the full window)
npm run shots      # saves a screenshot of every screen to ./shots  (use this to check your changes visually)
```

`PAGES=home,mods npm run shots` captures only some screens (login, home, events, mods, cosmetics, settings).
After any UI change, run `npm run shots` and look at the images before you say it is done.

## What is where

| Path | What it is |
|---|---|
| `main.js` | Electron main process. Frameless transparent window. Two sizes: small sign-in card (400x500), then full launcher (1280x800, min 1100x700). IPC: `win` (min/max/close) and `mode` (`login`/`app`). |
| `preload.js` | Exposes `window.dexter` to the page. Keep it narrow; add new capabilities here. |
| `src/index.html` | All screens in one file. Pages are `<section class="page" id="home|events|mods|cosmetics">` (the tab is called Cosmetics). Settings is a floating sheet, sign-in is `#login`. |
| `src/styles.css` | The whole stylesheet. Tokens at the top. Sections are labelled. |
| `src/app.js` | UI logic. **Sample data is at the top** (`EVENTS`, `INSTANCES`, `FRIENDS`, `SERVERS`, `TYPES`, `VERIFIED`, `WARD`). |
| `src/cosmetics-data.js` / `src/cosmetics3d.js` | Cosmetics tab: `cosmetics-data.js` is GENERATED by `npm run cosmetics` (packs the 42 real Minecraft cape textures from `assets/cosmetics` as data URIs, because WebGL cannot read file:// images). `cosmetics3d.js` builds the Dexter-original voxel hats and pixel-art pets (extruded sprites), the card thumbnails and the emote previews. **Licensing:** the cape textures are Mojang/Microsoft artwork (from minecraft.wiki); confirm rights before shipping publicly. Hats and pets are original (no official set exists). |
| `src/icons.js` | GENERATED by `npm run icons` (`tools/build-icons.js`). Never edit by hand. |
| `src/vendor/` | skinview3d (MIT) for the 3D Minecraft player. |
| `assets/` | Logos, app icon, event images (`events/`), Dexter server image (`servers/`), local fonts (`fonts/`). |
| `docs/DESIGN.md` | The design system: tokens, rules, motion. Read before touching styles. |
| `docs/INTEGRATION.md` | **Every place that is fake today and what to replace it with.** Start here for real work. |

## What is already live (real data, no key needed)

- Mods, modpacks, resource packs, data packs, shaders: **Modrinth API** (`https://api.modrinth.com/v2`), filtered by the selected instance's Minecraft version and loader.
- Server icons and player counts in the Servers panel: `api.mcsrvstat.us`.
- Player heads, bodies and skins: `mc-heads.net`.

Everything else (sign-in, launching, joining, registering for events, friends, capes, settings) is **sample data / visual only** until you wire it. See `docs/INTEGRATION.md`.

## Rules that keep the design intact (do not break these)

1. **Colors:** near-black `#070708` ground, one accent violet `#8D45C7` / `#B892FF`, white text. No orange, no neon, no gradients blobs, no extra accent colors (green is only for "online/active", red only for "live").
2. **Play button is purple** with a generated pixel texture of big 8px squares (`mosaic('#8d45c7', 8, 96, .1)` in `app.js`, `background-size:96px` in `.play::before`). Do not recolor it or make the pixels smaller.
3. **The window base is liquid glass on macOS** (client request, Nov 2026): `main.js` gives the window native vibrancy, and `html.glass` in `styles.css` lays a light grey tint over it with translucent cards. Still no CSS backdrop-filter on cards or bars.
4. **Cards use the one Up recipe** (`--card-fill` + `--card-edge` in `styles.css`) on a solid `#101012` base, so the grid does not show through them. Mod cards are even more opaque on purpose.
5. **The top bar has no outline.** The tab pill container does.
6. **Motion is subtle:** fades and 8-12px slides, `var(--ease)` only, 0.25-0.45s, nothing bounces or overshoots. Respect `prefers-reduced-motion`.
7. **Type:** Golos Text for UI, Pixelify Sans only for display (titles, podium numbers, Play). Nothing smaller than 13px. No emoji.
8. **Icons:** Solar "bold-duotone" via `tools/build-icons.js`. Do not add another icon library or hand-draw SVGs.
9. **Radius:** panels 22px, cards 18px, everything interactive is a pill (999px) except the Play button (10px) and the instance picker on Home (12px).
10. **Settings is black only** (no purple inside the sheet).
11. **The right panel (Servers / Friends) shows on Home only.** On other tabs it appears only while the Friends button is on.
12. The sign-in screen is its own small window; do not turn it back into a full-window page.
13. **Home hero:** when the event changes, only the picture (crossfade) and the title/description change. The two buttons (Play, instance picker) are created once and must never be re-rendered or animated. Do not use `innerHTML` on `.hero-main`.
14. **Support, Website and Discord live in one Links drop-down in the top bar, beside the logo on the left** (`#linksBtn` / `#linksMenu`) (Support = `mailto:team@dextercopilot.ai`, Dexter website = `https://dextercopilot.ai`, Discord = `https://discord.gg/CUREmvuPgf`). Links open in the system browser through `window.dexter.open()`; allowed hosts are listed in `main.js` (`LINK_HOSTS`). Change the Support address when Dexter has a real support page.
15. **There is no leaderboard and no past-events list.** They were removed on purpose; do not add them back.
16. **The app has its own name and data folder (`Dexter Launcher`).** Never name it plain `Dexter`: that is the Dexter desktop app's name and data folder, and the two would share (and corrupt) cache and storage.

## Working notes

- No build step: `index.html` loads `styles.css`, `icons.js`, `vendor/skinview3d.bundle.js`, `app.js` directly. Keep it that way unless you have a good reason; if you add a bundler, keep `npm run shots` working.
- `app.js` builds a lot of HTML with template strings. **Always run external text through `esc()`** (Modrinth titles, usernames, server names) before putting it in `innerHTML`.
- The CSP in `index.html` lists the allowed network hosts (`connect-src`). Add your backend host there when you add one.
- The window is transparent: rounded corners and the border are drawn in CSS (`.app`, `.login`). Do not give `html`/`body` a background (a rule already handles plain-browser previews).
- Assets in `assets/` are Dexter's brand files (logo from dextercopilot.ai, app icon, event artwork). Replace images by keeping the same filenames: `events/lava-race.jpg`, `battle-royale.jpg`, `squid-game.jpg`, `smp.jpg`, `manhunt.jpg`, `servers/dexter.jpg` (16:9, about 1920x1080, subject on the right, left third calm because text sits there).
